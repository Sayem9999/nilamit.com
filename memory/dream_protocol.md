# 🌙 Protocol: autoDream Consolidation

> Last Updated: April 29, 2026

## Purpose
The `autoDream` protocol is the final phase of any major task session. It ensures that session-specific lessons are distilled into the project's long-term memory.

## Consolidation Steps
1. **Review Task Logs**: Analyze the current [task.md](file:///c:/nilamit.com/task.md) and conversation for new insights.
2. **Fact Escalation**: 
    - Identify any new architectural decisions and add to [decisions.md](file:///c:/nilamit.com/memory/decisions.md).
    - Identify any bugs, tricky patterns, or performance optimizations and add to [lessons.md](file:///c:/nilamit.com/memory/lessons.md).
3. **Pruning**: 
    - Remove completed tasks from `task.md`.
    - Update `MEMORY.md` index if new files were added to the directory.
4. **Skepticism Check**: 
    - Verify that new "facts" are not hallucinations or one-off workarounds. If a change is temporary, do not escalate it to long-term memory.

## Frequency
Consolidate at the end of every high-priority feature implementation or complex debugging session.
